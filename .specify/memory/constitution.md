# eyesofish 的 GitHub 主页维护约定

## 核心原则

### 经历和成果可以核实

写入学历、实习、求职动态或项目成果时，以俞洋本人确认的信息或可核实的资料为依据。
写实验结果时，交代指标和比较基准。写开源贡献时，区分个人仓库中的实现、已提交的 PR 和已合并的改动。

### 链接直达对应作品

介绍项目时链接到项目仓库，介绍具体贡献时链接到相应的 PR 或提交。
验收新增或更换的链接时，打开目标页面，确认访客能看到正文描述的作品。

### 用 GitHub 的渲染效果验收排版

主页使用 GitHub 支持的 Markdown。调整标题、列表或图片后，在 GitHub Markdown 预览中检查受影响的段落。
发布前确认标题层级清楚、链接文字可读，新增图片有说明其内容的替代文本。

## 修改流程

用 `$speckit-specify` 记录本次改动面向谁、想改什么、读者会看到什么。
随后制定计划、拆分任务、修改 README，并逐项对照规格验收。

## 约定的修订

修改本约定时，在提交说明中写明原因，同步更新版本和修订日期。
重新定义或移除原则时升主版本，新增原则时升次版本，仅澄清措辞时升补丁版本。
