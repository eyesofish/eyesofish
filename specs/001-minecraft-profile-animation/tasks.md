# 实施任务 · GitHub 主页方块世界横幅

一个任务交付横幅、README 引用和回归测试。US1 是最小可展示版本，US2、US3 共用这份 GIF 和图片段落，分别验收。依据见[功能规格](spec.md)、[实现计划](plan.md)和[首页展示约定](contracts/readme-banner.md)。

## 阶段 1 · 环境

从仓库根目录运行命令，使用已选定的 Python 3.13、Pillow 13.0.0 和标准库 `unittest`。

## 阶段 2 · 共用设计

生成器和单测共用一份计算当前帧状态的纯函数。输入为帧序号，输出包括窗灯状态和云的水平偏移。绘图时直接使用这些值。构图、光照与时间边界见[场景时间表](data-model.md)。

## 阶段 3 · US1 观看完整的昼夜循环（P1）

- [X] T001 [US1] 在 `tests/test_render_banner.py` 写下表的时间边界测试，在 `scripts/render_banner.py` 实现帧状态及绘图，生成 `assets/block-world.gif`，在 `README.md` 的姓名标题后嵌入图片与约定的英文替代文本，并按 US2、US3 检查阅读体验。

**单元测试。** 用 `unittest.TestCase` 直接调用生成器的帧状态函数。用 `subTest` 逐组断言以下输入和预期。从仓库根目录运行 `python -m unittest discover -s tests -p "test_*.py" -v`。

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| 窗灯开关 | 第 27、28、59、60 帧 | 依次为灭、亮、亮、灭，分别覆盖第 7 秒和第 15 秒的前后边界。 |
| 云持续向右 | 第 0 至 12 帧，第 63 帧接第 0 帧 | 前 3 秒云向右移 12 个逻辑像素。跨接缝时，两帧的偏移差对 64 取模等于 1。 |

**成品检查。** 用 `python scripts/render_banner.py` 导出 GIF，再按[验收指南](quickstart.md)用 Pillow 读取实际文件。确认可解码为多帧、画幅 960 × 240、各帧时长为正、总计 16 000 毫秒、循环标记为 0。源画布为 320 × 80，以 250 毫秒为间隔绘制 64 个时刻。编码器可以合并相同帧。记录文件体积，优化目标为 2 MiB 以内。

**独立验收。** 从 GIF 载入算起，3 秒内云相对屋顶有可见位移。观察两轮，确认入夜亮灯、天亮熄灯，且接缝处没有空帧或位置跳变。

## 阶段 4 · US2 窄屏和宽屏阅读（P2）

在已包含图片的 GitHub 分支 README 上，分别用 375 和 1280 像素宽度检查浅色、深色主题。四种组合均能看全小屋，横幅没有引入横向滚动。用 `git diff 97cde68 -- README.md` 核对只新增图片段落，随后从页面打开 `software_reco`，在文末找到邮箱和 LinkedIn。

## 阶段 5 · US3 静止画面、朗读与加载失败（P2）

关闭 GitHub 的动图自动播放后刷新，观察 5 秒，确认木屋和草地静止可辨。用屏幕阅读器检查姓名标题、英文场景描述、第一段介绍的顺序。单独阻止 GIF 请求并刷新，确认正文仍可读、项目链接可用。Playwright 可辅助切换视口或拦截图片请求，账户播放偏好与朗读顺序在真实 GitHub 页面验收。

## 收尾、依赖与并行

先跑帧状态单测，再生成并解码 GIF，最后检查嵌入后的 README。US1 有成品即可观看，US2 和 US3 在 README 可预览后可以并行验收。只有 T001 一个实现任务。分别记录本地和 GitHub 实测结果，分支预览及发布后个人主页复核按[验收指南](quickstart.md)执行。
